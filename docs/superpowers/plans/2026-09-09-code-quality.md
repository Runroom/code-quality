## Research notes (from plan drafting, verified 2026-09-09)

- **PHPCS must be 4.0.4, not 3.x**: `slevomat/coding-standard` 8.31.1 (a spec-locked pin) declares `"squizlabs/php_codesniffer": "^4.0.1"`. The 3.x line (latest 3.13.6) cannot host the Slevomat cognitive sniff at that version.
- **composer-require-checker 4.24.0** (Packagist, 2026-03-20; requires PHP `~8.4.0 || ~8.5.0`; phar sha256 `35d1dfdd7aa94a750f4b4c9b0b22dd5e76b5e9e35fb910c8901f3dafd2ad2ab9`). composer-unused 0.9.6 phar sha256 `9560e8bd0c3e30ecb0dc6e6348d170c66ac175e715ae58b6e8b302978d5b9dab`. deptrac 4.7.1 and phpmd 2.15.0 are installed via Composer in isolated tool directories with locks generated by the orchestrator.
- **Grammars**: `tree-sitter-wasms@0.1.13` bundles 38 grammars built from ~0.20 grammar versions with tree-sitter-cli 0.20. Better option: the official grammar npm packages ship their own `.wasm`: `tree-sitter-typescript@0.23.2` (`tree-sitter-typescript.wasm`, `tree-sitter-tsx.wasm`), `tree-sitter-javascript@0.25.0`, `tree-sitter-php@0.24.2` (`tree-sitter-php.wasm`), `tree-sitter-python@0.25.0`. `web-tree-sitter@0.27.0` supports language ABI 13–15, API `import { Parser, Language } from 'web-tree-sitter'`, `Parser.init({ locateFile })`, `Language.load(path)`, `node.descendantForIndex()`; indices are JS-string (UTF-16) indices, so the Bayer byte-offset→string-index conversion is kept.
- **jscpd 5.2.0 is a Rust binary**: `--baseline <file> --update-baseline`, baseline file `{version:1, fingerprints:{hash:count}}`, JSON report `statistics.total.sources`, `duplicates[]`.
- **complexipy 8.0.1**: `--output-format json` has no line numbers; `--output-format sarif` has `region.startLine` and message `Function 'x' has a cognitive complexity of N, which exceeds the maximum allowed complexity of M.` → the blocking parser reads SARIF.
- Output flags confirmed: `phpmd <paths> json <ruleset>`, `phpcs --report=json`, `composer-unused --output-format=json`, `composer-require-checker check --output=json`, `phpstan analyse --error-format=json`, `deptrac analyse --formatter=json --output=<file>`, `knip --reporter json`, `depcruise --output-type json`, `ruff check --output-format json`, `deptry --json-output <file>`, `vulture` text `path:line: unused <typ> '<name>' (NN% confidence)` exit 3 on findings, `lint-imports` text (`<name> KEPT|BROKEN`, `X is not allowed to import Y:`, `a.b -> c.d (l.N)`).

# Implementation plan: Runroom/code-quality v1

**Goal.** Build `github.com/Runroom/code-quality`: one TypeScript CLI (`code-quality`) shipped as a Docker image and a reusable GitHub workflow that runs an incremental, reduction-only quality gate (complexity, cognitive complexity, exact duplication, unused code, optional architecture) over TS/JS, PHP and Python consumer repositories, with normalized `<file> | <rule> | <anchor>` baselines, pinned tools, and a repository that passes its own gate with empty baselines.

**Architecture.** `src/cli` (commander commands) → `src/core` (config + detection + canonical hash, snapshot/compare state machine, process runner with artifacts and version verification, web-tree-sitter anchor service, reporting) → `src/registry.ts` (the only list of concrete adapters) → `src/checks/{ts,php,python,shared}` (one adapter per pinned tool: generates temp config, declares the command, parses native output strictly into `Findings`). esbuild bundles everything into `dist/cli.js` plus copied WASM assets in `dist/assets/`; the multi-stage Dockerfile installs all pinned tools and exposes `code-quality` from `/work` as the `node` user.

**Tech stack.** Node 24, TypeScript 5.9.3 (strict), pnpm 10, vitest 5.0.0, esbuild 0.28.2, commander 15.0.0, zod 4.5.4, yaml 2.9.0, picomatch 4, web-tree-sitter 0.27.0, tree-sitter-typescript 0.23.2, tree-sitter-javascript 0.25.0, tree-sitter-php 0.24.2, tree-sitter-python 0.25.0, oxlint 1.82.0 (own lint), Docker base `node:24-trixie-slim`, actionlint 1.7.12 via `rhysd/actionlint:1.7.12`.

**Spec path.** `docs/superpowers/specs/2026-09-09-code-quality-design.md` (copied from `/private/tmp/claude-502/-Users-alexsanchez-Projects/610d1add-3d39-4e15-b542-4c2cb64b8986/scratchpad/2026-09-09-code-quality-design.md`). Plan path: `docs/superpowers/plans/2026-09-09-code-quality.md`.

Function mode target = innermost function-like node containing the offset (falls back to innermost container, then error). Block mode target = innermost block-kind node containing the offset (error when none). `tree.rootNode.hasError` → `QualityError("<file>: grammar could not parse the file")`.

```ts
// service.ts core
import { Language, Parser } from "web-tree-sitter";
export function createAnchorService(dir = assetsDir()): AnchorService {
  const languages = new Map<Grammar, Promise<Language>>();
  let ready: Promise<void> | undefined;
  const init = () => (ready ??= Parser.init({ locateFile: () => join(dir, "web-tree-sitter.wasm") }));
  const load = (g: Grammar) => languages.get(g) ?? languages.set(g, init().then(() => Language.load(join(dir, `tree-sitter-${g}.wasm`)))).get(g)!;
  return {
    async anchor(file, source, byteOffset, blockMode) {
      const grammar = grammarFor(file);
      const parser = new Parser(); parser.setLanguage(await load(grammar));
      const tree = parser.parse(source); parser.delete();
      if (!tree || tree.rootNode.hasError) fail(`${file}: grammar could not parse the file`);
      const index = byteOffsetToIndex(source, byteOffset);
      const leaf = tree.rootNode.descendantForIndex(index) ?? fail(`${file}: cannot identify diagnostic anchor at byte ${byteOffset}`);
      const target = climbToTarget(grammar, leaf, source, blockMode) ?? fail(`${file}: cannot identify diagnostic anchor at byte ${byteOffset}`);
      const path = structuralPath(grammar, target, source); tree.delete(); return path;
    },
  };
}
```

`climbToTarget` walks `node.parent` until `labelFor` returns a function/container label (function mode) or a block label (block mode). `structuralPath` climbs collecting labelled ancestors, computing ordinals by scanning the structural parent's subtree for same-label structural nodes whose nearest structural ancestor is that parent (helper `structuralChildren(parent)` using a stack walk that does not descend into structural nodes). → pass.

  command: (ctx) => ({ bin: "oxlint", args: ["-c", join(ctx.tempDir, "oxlintrc.quality.json"), "--format", "json", ...ctx.paths], exitCodes: [0] }),
  parse: (ctx, result) => oxlintFindings(ctx, JSON.parse(result.stdout)),
};

export async function oxlintFindings(ctx: CheckContext, input: unknown): Promise<Findings> {
  const report = reportSchema.parse(input);
  if (report.number_of_files === 0) fail("oxlint scanned no files");
  const findings = new FindingsBuilder();
  for (const d of report.diagnostics) {
    const pattern = METRICS[d.code];
    if (!pattern || d.severity !== "warning") fail(`Unbaselined diagnostic: ${d.filename} ${d.code}: ${d.message}`);
    const file = relativize(ctx.root, d.filename); assertInScope(file, ctx.paths);
    const anchor = await ctx.anchor.anchor(file, ctx.readSource(file), d.labels[0]!.span.offset, d.code === "eslint(max-depth)");
    findings.add(file, d.code, anchor, extractMeasurement(pattern, d.message, d.code));
  }
  return findings.build();
}
